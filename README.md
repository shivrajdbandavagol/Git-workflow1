1. Understanding the Git Workflow
Git is a distributed version control system that helps developers track changes in their code, maintain different versions of a project, collaborate with other developers, and safely experiment with new features.
GitHub is an online platform that hosts Git repositories, allowing developers to share code and collaborate.
A typical Git workflow follows these stages:
Working Directory → Staging Area → Local Repository → Remote Repository
1. Working Directory: The folder where you create and modify files.
2. Staging Area: The area where you select the changes you want to include in your next commit.
3. Local Repository: The repository on your computer that stores your project's commit history.
4. Remote Repository: A repository hosted on GitHub or another Git server.
Important Git commands
Command	Purpose
git init	               Initialize a new Git repository
git status	             Check the current state of your files
git add	                 Stage changes
git commit	             Save staged changes as a snapshot
git log	                 View commit history
git branch	             List or manage branches
git switch	             Switch between branches
git merge	               Combine changes from branches
git push	               Upload local commits to a remote
git pull	               Fetch and integrate remote changes
git clone                Copy an existing repository
